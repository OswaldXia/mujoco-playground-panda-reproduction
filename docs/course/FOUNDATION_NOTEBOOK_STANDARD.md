# v0.12 教材级 Notebook 标准

## 目的

教材级 Notebook 必须让尚未学习机器人学与强化学习、但已经会 Python 和 Git 的
学习者，仅依靠课程材料建立可复述、可计算、可编码、可迁移到真实项目的概念模型。
它不是章节摘要，也不是把若干代码格放进浏览器。

现有 v0.11 Notebook 保留为交互练习。新建或重写的基础 Notebook 只有满足本文件
全部要求，才能标记为 v0.12 foundation。

## 内容结构

每本教材级 Notebook 按以下顺序组织：

1. **前置知识和本节问题**：明确已经假定什么、学完能回答什么；
2. **开始前诊断**：答案默认留空，不展示正确答案，不阻止空内核运行；
3. **严格定义**：每个新对象给出集合、域和值域、语义和成立条件；
4. **符号、单位与 shape**：所有符号在首次使用前定义；
5. **直观解释**：说明定义解决的实际问题，同时标出类比的边界；
6. **原理与推导**：从已知结论逐步推出新公式，不用“显然”“容易得到”跳步；
7. **Worked example**：至少一个可纸笔复算的完整数值例子；
8. **带注释的最小实现**：注释解释数学语义、单位、frame、shape 和设计原因；
9. **可视化或反事实实验**：先预测，只改变一个变量，再解释变化；
10. **故意出错**：展示会产生合理数值、但语义错误的常见 bug；
11. **分层练习**：模仿、补全、迁移三个层级，逐渐撤掉脚手架；
12. **项目源码连接**：读取或定位真实项目文件，明确简化模型与正式实现的对应关系；
13. **自测**：执行断言检查数学和程序不变量；
14. **Exit ticket**：答案默认留空；通过标准包含解释，不只包含运行成功；
15. **参考答案和反思**：答案放在折叠区，最后给出个人学习记录要求。

## 严格定义的最低要求

一个定义至少回答：

- 对象属于什么集合；
- 输入和输出分别是什么；
- 数字表示哪个物理或概率对象；
- 使用哪个坐标系、单位和数组维度；
- 哪些约束使它成为合法对象；
- 它与相邻概念有什么区别。

例如不能只写“旋转矩阵表示旋转”，而应说明
$R\in SO(3)=\{R\in\mathbb{R}^{3\times3}\mid R^TR=I,\det(R)=1\}$，并解释
列向量、输入输出表达系以及为什么反射矩阵不属于 $SO(3)$。

## 代码注释标准

注释不逐字翻译 Python。它们应解释读者无法从语法直接得知的内容：

- 数组每一维的语义和 shape；
- 数值单位；
- 坐标表达系；
- 为什么选择此算法或乘法顺序；
- 哪个断言对应哪个数学不变量；
- 教学实现与项目实现之间省略了什么。

关键变量优先使用带 frame 方向的名字，例如 `world_from_base`，避免只写 `T1`。

## 时间与拆分规则

- 一本微课程建议 60–120 分钟，最长 150 分钟；
- 若需要定义超过 7 个新概念，应继续拆分；
- 一次只引入一个主要认知跳跃；
- 不以减少解释换取较短的预计时间；
- 每本必须能在 Mac CPU、项目 `.venv` 和空 kernel 中运行。

## 证据边界

Notebook 运行通过证明教学代码可执行，不证明学习者已经掌握，也不生成正式策略
性能证据。正式训练、评估、checkpoint、协议和日志仍由 `reproduction/` 命令行工具
产生。精选轨迹只能解释行为，不能估计总体成功率。

## 发布验收

- 新符号在使用前已有定义；
- 至少一段逐步推导和一个手算例子；
- 至少一个有 frame/unit/shape 注释的代码实现；
- 诊断和 Exit ticket 没有预填正确答案；
- 故意错误不会中断 `Restart Kernel and Run All`；
- 从空 kernel 执行通过，且源文件不保存输出；
- Markdown 公式、相对链接、版本元数据和项目源码锚点通过自动校验；
- 至少一名目标学习者试学后，才将样板推广到其他章节。
